# ADR-0043: EBS snapshot permissions on AWS

- Status: accepted
- Date: 2026-11-26
- Pack: FP-4 (AWS), refines FP4-F-09

## Context

The EBS CSI driver of the `aws-csi` preset runs on the control plane nodes and uses the instance
profile `control-plane.cluster-api-provider-aws.sigs.k8s.io`. With the default configuration of
`clusterawsadm bootstrap iam create-cloudformation-stack` (CAPA v2.13.1), this role has the cloud
provider policy: volumes can be created, attached and resized, but snapshots cannot. Since 0.21.1 the
preset runs the snapshot sidecar; a user's Velero backup then failed with HTTP 403 on
`ec2:DescribeSnapshots`.

A policy attached by hand in the AWS console does not last: the next stack update by clusterawsadm
removes it. FP4-F-09 forbids the app to create IAM resources itself.

`clusterawsadm` offers two ways: `spec.controlPlane.enableCSIPolicy` (a policy generated by CAPA) and
`spec.controlPlane.extraPolicyAttachments` (any managed policy).

## Decision

- The command shown by the credential test creates or updates the stack with a bootstrap
  configuration that attaches the AWS managed policy `AmazonEBSCSIDriverPolicy` to the control plane
  role. AWS maintains this policy along with the driver; CAPA's generated policy may lag behind.
- Only the control plane role gets the policy. On the worker nodes every pod could use it through the
  instance metadata service.
- The credential test simulates `ec2:DescribeSnapshots` for the control plane role
  (`iam:SimulatePrincipalPolicy`), which covers managed and inline policies and permission
  boundaries. A denied call is a warning: the test passes, shows "Setup needed" and the command.
  Without `iam:SimulatePrincipalPolicy` the check is marked as not verified.

## Consequences

- New AWS accounts get snapshot permissions with the first stack.
- Existing accounts see the warning after the next credential test. The command updates the stack;
  running instances get the permissions without a restart and no cluster changes.
- An earlier custom bootstrap configuration must be merged into the shown one, or the update removes
  its settings.
- The IAM user of the app needs `iam:SimulatePrincipalPolicy` in addition to `iam:GetRole` and
  `iam:GetInstanceProfile` for the check.
- Service control policies of AWS Organizations are not part of the simulation.
